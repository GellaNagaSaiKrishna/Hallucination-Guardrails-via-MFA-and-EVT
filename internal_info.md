## Part 1: Core Mathematical Concepts — Deep Dive

### 1.1 Why Standard Approaches Fail in High Dimensions

Dense language embeddings (d = 384 to 768 dimensions) reside on low-dimensional, curved
submanifolds within R^d. Two key failure modes arise:

**Failure of Full GMM:**
A full covariance matrix has d*(d+1)/2 parameters per component.
For d = 768 and K = 10 clusters: ~2.95 million parameters.
In finite corpora (N ~10,000 documents), sample covariance matrices become singular
(det(Sigma_k) ~= 0), causing EM updates to numerically collapse.

**Failure of Diagonal / Spherical GMM:**
Assuming diagonal covariance discards all correlated dimensions along which semantic meaning
varies, leading to high false-positive rates on boundary queries.

**Failure of Cosine/Euclidean Thresholds:**
An in-distribution query may lie far from the global centroid but directly inside a sparse
valid cluster. An adversarial OOD query may fall near the global mean in an empty void.
Neither threshold captures manifold shape.

---

### 1.2 Mixture of Factor Analyzers (MFA) — Full Derivation

Factor Analysis assumes an observed d-dimensional vector x is generated by a low-dimensional
continuous latent factor y in R^r (r << d, e.g., r = 16 or 32):

    y ~ N(0, I_r)
    x | y ~ N(mu + W*y, Psi)

where:
  - W in R^{d x r} is the FACTOR LOADING MATRIX (captures shared latent variance)
  - Psi = diag(psi_1, ..., psi_d) is the UNIQUENESS MATRIX (component-wise independent noise)

Marginalizing out the latent factor y:

    p(x) = integral p(x|y) p(y) dy = N(x | mu, W*W^T + Psi)

For a MIXTURE OF FACTOR ANALYZERS with K components:

    p(x) = sum_{k=1}^K pi_k * N(x | mu_k, W_k*W_k^T + Psi_k),   sum_k pi_k = 1

Free parameters per cluster: d*r + d - r*(r-1)/2  (instead of d*(d+1)/2 for full GMM)
For d=768, r=16: ~12,900 parameters — a 95.6% parameter reduction, while preserving
anisotropic correlation structure.

---

### 1.3 Custom Expectation-Maximization (EM) — Step-by-Step Derivation

The EM algorithm alternates between computing posterior distributions over latent variables
and analytically updating model parameters to maximize the expected complete-data log-likelihood.

**--- E-STEP: Compute posterior quantities ---**

For each sample x_i and cluster k:

  Responsibility (posterior mixture assignment):
    gamma_{ik} = P(z_i = k | x_i) = [pi_k * N(x_i | mu_k, Sigma_k)] / [sum_j pi_j * N(x_i | mu_j, Sigma_j)]

  Posterior latent factor weight matrix (r x d):
    beta_k = (I_r + W_k^T * Psi_k^{-1} * W_k)^{-1} * W_k^T * Psi_k^{-1}

  Conditional latent factor mean (r-vector):
    E[y_i | x_i, z_i=k] = beta_k * (x_i - mu_k)

  Conditional latent factor second moment (r x r matrix):
    E[y_i y_i^T | x_i, z_i=k] = I_r - beta_k * W_k + E[y_i|...] * E[y_i|...]^T

**--- M-STEP: Update all parameters ---**

  Mixture weights:
    pi_k = (1/N) * sum_i gamma_{ik}

  Cluster means:
    mu_k = [sum_i gamma_{ik} * x_i] / [sum_i gamma_{ik}]

  Factor loadings W_k:
    W_k_new = [sum_i gamma_{ik} * (x_i - mu_k) * E[y_i|x_i,k]^T]
              * [sum_i gamma_{ik} * E[y_i y_i^T | x_i, k]]^{-1}

  Diagonal uniquenesses Psi_k:
    Psi_k_new = diag { (1 / sum_i gamma_{ik}) *
                sum_i gamma_{ik} * [(x_i-mu_k)(x_i-mu_k)^T - W_k_new * E[y_i|...] * (x_i-mu_k)^T] }
    (Only diagonal elements are retained.)

  NUMERICAL FLOOR: Psi_{k,jj} >= epsilon * Var(X_{:,j}), epsilon = 1e-4
  This prevents any uniqueness from collapsing to zero.

---

### 1.4 Woodbury Low-Rank Inversion — Why and How

**The Problem:**
Evaluating (x - mu_k)^T * Sigma_k^{-1} * (x - mu_k) requires inverting Sigma_k = W_k*W_k^T + Psi_k.
Direct inversion:  O(d^3) per cluster per query  ==>  768^3 ~= 453 million operations. Infeasible.

**The Solution — Woodbury Matrix Identity:**

    (W*W^T + Psi)^{-1} = Psi^{-1} - Psi^{-1} * W * (I_r + W^T * Psi^{-1} * W)^{-1} * W^T * Psi^{-1}

Computational breakdown:
  - Psi is diagonal  =>  Psi^{-1} is element-wise reciprocal: O(d)
  - (I_r + W^T * Psi^{-1} * W) is an r x r matrix  =>  Cholesky inversion: O(r^3)
  - Total cost per query per cluster: O(r^3 + r^2*d)
  - For r=16, d=768: ~6,400 operations vs. 453 million. 70,000x speedup.

**Log-Determinant (for likelihood computation):**

    log|Sigma_k| = sum_j log(psi_{k,j}) + 2 * sum_j log(L_{jj})

where L is the Cholesky factor of (I_r + W_k^T * Psi_k^{-1} * W_k).

**Minimum Mahalanobis Distance across K clusters:**

    D_M^2(q) = min_{k=1..K} (q - mu_k)^T * Sigma_k^{-1} * (q - mu_k)

---

### 1.5 Bayesian Information Criterion (BIC) for Model Selection

Too few clusters (K too small): Underfits multi-modal semantics.
Too many clusters (K too large): Isolates individual outlier chunks as singleton clusters.

BIC penalizes model complexity:

    BIC = -2 * log(L_hat) + P * log(N)

where:
  - log(L_hat) = maximized incomplete log-likelihood
  - P = K * (r*d + d - r*(r-1)/2) + (K-1) = number of free parameters
  - N = number of training samples

Optimal K* = argmin_K BIC(K)
Grid search over K in {2, 4, 8, 16} and r in {8, 16, 32}.

---

### 1.6 Extreme Value Theory (EVT) & Weibull Tail Calibration

**The Problem with Static Thresholds:**
High-dimensional Mahalanobis distances follow chi-squared-like distributions with heavy right tails.
A fixed cutoff on D_M^2(q) causes many false alarms on boundary queries that are technically
in-distribution but lie in sparse regions.

**Theoretical Foundation:**
By the Fisher-Tippett-Gnedenko Theorem and Pickands-Balkema-de Haan Theorem, the distribution
of extreme deviations beyond a high threshold tau_0 asymptotically follows an extreme value
distribution (Weibull or Generalized Pareto Distribution).

**Fitting Procedure:**

  Step 1: Compute D_M^2(x_v) for all x_v in the held-out validation split.
  Step 2: Set tail threshold tau_0 = 90th percentile of these validation distances.
  Step 3: Extract exceedances: E = {D_M^2(x_v) - tau_0  |  D_M^2(x_v) > tau_0}
  Step 4: Fit Weibull parameters (kappa, lambda) via Maximum Likelihood:
            F(e) = 1 - exp(-(e/lambda)^kappa)
            using scipy.stats.weibull_min.fit(E, floc=0)

**Scoring a Query:**

  Survival probability (p-value under H_0: query is in-distribution):

    S(q) = exp( -( max(0, D_M^2(q) - tau_0) / lambda )^kappa )

  Decision rule:
    S(q) < alpha (alpha = 0.01)  =>  REJECT as Out-of-Distribution
    S(q) >= alpha               =>  PASS to retriever and LLM

WEEK 2: Custom EM Derivation & MFA Implementation
=========================================================================

GOAL: Implement the Mixture of Factor Analyzers from scratch in NumPy/SciPy
      with the Woodbury low-rank inversion for fast, stable scoring.

STEP 2.1 — Model Initialization
----------------------------------
  Tasks:
    [ ] Split corpus: 80% train, 20% validation (stratified if domain-labeled)
    [ ] Initialize cluster centers mu_k via KMeans(n_clusters=K, n_init=10)
    [ ] For each cluster k:
          * Collect assigned points; compute residuals
          * Run truncated SVD on residuals to get initial W_k (top-r left singular vectors * sqrt(singular values))
          * Set initial Psi_k = diagonal of cluster sample covariance - diag(W_k * W_k^T), clipped to be positive
    [ ] Set pi_k = 1/K for all k

STEP 2.2 — Vectorized E-Step
-------------------------------
  Tasks:
    [ ] For each cluster k, precompute:
          inv_psi_k = 1.0 / psi_k                             # shape (d,)
          M_k = I_r + (W_k.T * inv_psi_k) @ W_k               # shape (r, r)
          L_k = np.linalg.cholesky(M_k)                        # Cholesky factor
    [ ] Compute log-determinant:
          log_det_k = np.sum(np.log(psi_k)) + 2*np.sum(np.log(np.diag(L_k)))
    [ ] Compute Mahalanobis distance via Woodbury for all N points at once:
          delta = X - mu_k                                     # (N, d)
          term1 = np.sum(delta**2 * inv_psi_k, axis=1)         # (N,)  Psi^{-1} quadratic
          v = delta @ (W_k * inv_psi_k)                        # (N, r)
          sol = scipy.linalg.solve_triangular(L_k, v.T)        # (r, N)
          term2 = np.sum(sol**2, axis=0)                       # (N,)
          maha_sq = term1 - term2
    [ ] Compute log-likelihood: log_lik_k = -0.5*(d*log(2pi) + log_det_k + maha_sq)
    [ ] Compute responsibilities using log-sum-exp trick to prevent underflow:
          log_resp = log_lik_k + log(pi_k)  for each k
          gamma_{:,k} = exp(log_resp_k - logsumexp(log_resp, axis=1, keepdims=True))
    [ ] Compute latent factor posteriors beta_k, E[y_i|...], E[y_i y_i^T|...]

STEP 2.3 — Vectorized M-Step
-------------------------------
  Tasks:
    [ ] Update pi_k, mu_k as described in Section 1.3
    [ ] Update W_k using the weighted cross-covariance formula
    [ ] Update Psi_k; retain only diagonal; apply numerical floor:
          Psi_k = max(Psi_k, eps * X_variance)
    [ ] Re-precompute Cholesky factors for next E-step

STEP 2.4 — Convergence Monitoring
------------------------------------
  Tasks:
    [ ] Compute incomplete log-likelihood after each iteration
    [ ] Stop when relative change < 1e-5 OR max_iter = 50 reached
    [ ] Plot log-likelihood curve vs. iteration to verify monotone increase

STEP 2.5 — BIC-Based Hyperparameter Search
---------------------------------------------
  Tasks:
    [ ] Grid: K in {2, 4, 8, 16},  r in {8, 16, 32}
    [ ] For each (K, r): fit MFA, compute BIC = -2*log_L + P*log(N)
    [ ] Select (K*, r*) = argmin BIC
    [ ] Plot BIC heatmap (K vs. r)

STEP 3.3 — Implement Guardrail Scoring Function
-------------------------------------------------
  def compute_ood_score(q_embedding, mfa_model, evt_params, alpha=0.01):
      d_sq = mfa_model.min_mahalanobis(q_embedding)
      exceedance = max(0.0, d_sq - evt_params["tau0"])
      if exceedance == 0.0:
          return "IN_DISTRIBUTION", 1.0
      p_val = np.exp(-((exceedance / evt_params["lambda"]) ** evt_params["kappa"]))
      label = "OOD" if p_val < alpha else "IN_DISTRIBUTION"
      return label, p_val

STEP 3.4 — Build LangChain GuardrailRetriever Wrapper
-------------------------------------------------------
  class GuardrailRetriever(BaseRetriever):
      def __init__(self, mfa_model, evt_params, base_retriever, alpha=0.01):
          self.mfa = mfa_model
          self.evt = evt_params
          self.retriever = base_retriever
          self.alpha = alpha

      def _get_relevant_documents(self, query: str):
          q_emb = embed(query)
          label, p_val = compute_ood_score(q_emb, self.mfa, self.evt, self.alpha)
          if label == "OOD":
              return []   # Guardrail triggered; RAG bypassed
          return self.retriever.get_relevant_documents(query)
